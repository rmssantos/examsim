AI-103 Labs: What to Expect and How to Practise in Foundry

Prepare for the skills a lab could test without relying on rumours that your AI-103 appointment will definitely include one.

Reviewed September 4, 2026 · Skills measured as of April 16, 2026

Will AI-103 have a lab?

Treat a lab as possible, not guaranteed. Microsoft does not publish a fixed lab schedule for AI-103 on the current certification or study-guide pages. Candidate reports can describe one appointment, but they cannot predict yours.

Microsoft's official certification exam FAQ is deliberately conditional: if an exam contains labs, its introduction tells you how many labs and tasks are included. Read that introduction before starting and plan your time from the format shown there.

What Microsoft actually confirms

The Foundry practice loop that matters

The official AI-103 study guide measures five domains. The first two account for 55–65% of the blueprint, so build one small solution that forces you to make the following decisions.

  1. Create the project deliberately. Choose the resource, project, region, deployment, connection, and model for stated requirements. Record why each choice fits.
  2. Secure the path. Use managed identity and the narrowest suitable role. Be able to explain private networking, keyless access, quotas, rate limits, and cost controls.
  3. Ground an application. Ingest a small document set, configure search, retrieve relevant passages, and inspect whether the answer is supported by those passages.
  4. Add an agent tool. Define a clear tool schema, restrict what it can do, test expected and unexpected inputs, and inspect the trace rather than trusting the final text.
  5. Evaluate and observe. Compare runs for quality, groundedness, safety, latency, and failures. Change one variable at a time and explain the result.
  6. Cover the smaller domains. Complete focused exercises for vision, text and speech, and information extraction so you can select the simplest suitable capability.

Microsoft's Foundry training hub links current modules for project setup, model deployment, apps, agents, evaluation, and safeguards. Use those modules to build the workflow, then repeat the critical steps without following the page line by line.

Turn practice into a lab-style drill

Before

Write outcomes, not clicks

Create a short task list such as “deploy a suitable model”, “grant the app access without a key”, or “ground the agent on these files”. Include a way to verify every outcome.

During

Work from dependencies

Start long-running provisioning first, continue with independent tasks, and avoid changing unrelated defaults. Keep a checklist because a successful click is not proof that the requested state exists.

After

Inspect the final state

Verify deployments, roles, connections, indexes, agent tools, and test results from the resource itself. Then delete the practice resources you no longer need to control cost.
